# حوّل — كل حساباتك في رابط واحد

منصة SaaS عربية بسيطة: يسجّل المستخدم، يضيف حساباته البنكية ومحافظه، ويحصل
على صفحة عامة برابط قصير ورمز QR يشاركها مع الآخرين. الزائر ينسخ بيانات أي
حساب بضغطة واحدة، بلا تسجيل دخول.

> **نطاق المنصة:** عرض بيانات الحسابات ومشاركتها وتخصيصها والاشتراك فقط.
> لا فواتير، ولا عربون، ولا متابعة تحويلات. المنصة **لا تستقبل ولا توجّه**
> أي أموال بين الزائر وصاحب الصفحة.

---

## التشغيل السريع

يلزم **Node 18.18 أو أحدث** (جُرّب على 22).

```bash
git clone https://github.com/suad8/sud8.git
cd sud8/hawwil
npm install

cp .env.example .env
```

ولّد سرًا وضعه في `APP_SECRET` داخل `.env`:

```bash
openssl rand -hex 32
```

على ويندوز بلا openssl:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

ثم:

```bash
npm run setup    # prisma generate + db push + بيانات تجريبية
npm run dev
```

افتح <http://localhost:3000>.

بقية حقول `.env` تُترك فارغة — التطبيق يعمل بها كما هي.

**للدخول:** اذهب إلى `/login`، أدخل أي بريد، ثم **انسخ الرمز من طرفية
الخادم** (يُطبع هناك لأن SMTP غير مضبوط) — كما يظهر في الصفحة نفسها أثناء
التطوير.

بيانات تجريبية جاهزة بعد `npm run setup`:

| العنصر | القيمة |
| --- | --- |
| بريد تجريبي | `demo@example.com` |
| صفحة عامة | <http://localhost:3000/u/demo> |

## الإعداد الخارجي المطلوب

كل ما يلي **اختياري للتطوير** وإلزامي بدرجات في الإنتاج.

### 1. قاعدة البيانات

**PostgreSQL** هو الافتراضي — مطلوب للنشر لأن قرص الحاوية مؤقت.

```
DATABASE_URL="postgresql://user:pass@host:5432/hawwil?schema=public"
```

ثم `npm run db:migrate`.

للتطوير المحلي بلا خادم Postgres، بدّل `provider` في
`prisma/schema.prisma` إلى `"sqlite"` واستخدم `DATABASE_URL="file:./dev.db"`
ثم `npm run db:push`. لا ترفع هذا التبديل إلى الإنتاج.

### 2. البريد الإلكتروني (رموز التحقق)

بدون إعداد، تُطبع الرموز في طرفية الخادم — مقبول للتطوير فقط. **في الإنتاج
يرفض التطبيق الإرسال ويرمي خطأ** بدل أن يفشل صامتًا.

للتفعيل:

عبّئ `SMTP_HOST` و`SMTP_PORT` و`SMTP_FROM` في `.env` — و`SMTP_USER`/`SMTP_PASS`
إن كان المزوّد يطلب مصادقة. `nodemailer` مثبّت والكود جاهز، لا خطوة أخرى.

### 3. بوابة الدفع (اشتراك المنصة فقط)

| القيمة | السلوك |
| --- | --- |
| `manual` (افتراضي) | لا بوابة خارجية. الطلب يُسجَّل بحالة «معلّق» ويفعّله المدير من `/admin`. يعمل بلا مفاتيح. |
| `moyasar` | تكامل جاهز — يحتاج `PAYMENTS_SECRET_KEY` و`PAYMENTS_WEBHOOK_SECRET`. |
| `tap` / `stripe` | هيكل جاهز في `src/lib/payments.ts`؛ أكمل نقاط النهاية وتحقق التوقيع. |

الويب هوك على `POST /api/billing/webhook` ويتحقق من توقيع HMAC-SHA256 بمقارنة
ثابتة الزمن قبل لمس قاعدة البيانات.

### 4. المدير

ضع بريدك في `ADMIN_EMAILS` (مفصولة بفاصلة). يُرقّى الحساب إلى `ADMIN`
تلقائيًا عند أول تسجيل دخول، ولوحة الإدارة على `/admin`.

### 5. الباقات والأسعار

كلها من `.env` بلا لمس الكود:

```
FREE_MAX_ACCOUNTS="3"
PRO_MAX_ACCOUNTS="30"
PRO_PRICE_HALALAS="2900"   # 29.00 ر.س
PRO_CURRENCY="SAR"
```

## النشر على Railway

المستودع مجهّز بالكامل — `railway.json` والهجرات موجودة، فالخطوات كلها في المتصفح.

### 1. أنشئ المشروع

1. ادخل <https://railway.app> وسجّل بحساب GitHub
2. **New Project** ← **Deploy from GitHub repo** ← اختر `suad8/sud8`
3. في إعدادات الخدمة ← **Settings** ← **Source**:
   - **Branch**: `claude/project-overview-o08gxh`
   - **Root Directory**: `hawwil` ← **خطوة إلزامية**، فالمشروع داخل مجلد فرعي

### 2. أضف قاعدة البيانات

داخل المشروع: **+ New** ← **Database** ← **Add PostgreSQL**.

Railway يحقن `DATABASE_URL` في خدمة التطبيق تلقائيًا. **لا تضبطه يدويًا.**
لو لم يُحقَن، اربطه من **Variables** ← **Add Reference** ← اختر Postgres.

### 3. اضبط المتغيّرات

في خدمة التطبيق ← **Variables**:

| المتغيّر | القيمة |
| --- | --- |
| `APP_SECRET` | ناتج `openssl rand -hex 32` |
| `ADMIN_EMAILS` | بريدك — يصير مديرًا عند أول دخول |
| `SMTP_HOST` | مثلًا `smtp.resend.com` |
| `SMTP_PORT` | `587` |
| `SMTP_USER` | مستخدم المزوّد |
| `SMTP_PASS` | مفتاح المزوّد |
| `SMTP_FROM` | `حوّل <no-reply@yourdomain.com>` |

`APP_URL` **اتركه فارغًا** — يُشتق تلقائيًا من `RAILWAY_PUBLIC_DOMAIN`.

> **SMTP إلزامي في الإنتاج.** الدخول يتم برمز يصل بالبريد، وبدون SMTP
> يرفض التطبيق الإرسال — فلن تتمكن من تسجيل الدخول. للبداية السريعة:
> [Resend](https://resend.com) مجاني حتى 3000 رسالة شهريًا.

### 4. فعّل النطاق

**Settings** ← **Networking** ← **Generate Domain**.

بعد أول نشر أعد التشغيل مرة واحدة (**Deployments** ← **Redeploy**) حتى
يلتقط التطبيق النطاق الجديد في `APP_URL`.

### 5. تحقق

- افتح النطاق — يجب أن تظهر الصفحة الرئيسية
- `/login` ← أدخل بريدك ← يصلك الرمز على الإيميل
- بعد الدخول: `/dashboard/setup` لإنشاء صفحتك، و`/admin` للوحة الإدارة

### ما يحدث عند كل نشر

```
npm run build                          # prisma generate + next build
npx prisma migrate deploy && npm start # يطبّق الهجرات ثم يشغّل الخادم
```

`migrate deploy` آمن للتكرار — يطبّق الهجرات الناقصة فقط ولا يمسّ بياناتك.

### ملاحظات

- **لا تشغّل `npm run db:seed` على الإنتاج** — ينشئ حساب `demo@example.com` تجريبيًا
- الصور مخزّنة في قاعدة البيانات، فلا تحتاج تخزينًا خارجيًا ولا تضيع عند النشر
- تحديد المعدّل في الذاكرة يكفي نسخة واحدة؛ مع التوسّع انقله إلى Redis
  (`src/lib/ratelimit.ts` — واجهة `consume()` تبقى كما هي)

### لماذا `--webpack` في أمر البناء

Turbopack — المُجمِّع الافتراضي في Next 16 — ينهار على هذا المشروع:

```
panicked at crates/next-code-frame/src/highlight.rs:1021
end byte index 93 is not a char boundary; it is inside 'م'
```

يقطع نصًا عند فهرس بايت فيقع داخل محرف UTF-8 متعدد البايتات. الشيفرة
عربية بالكامل فالانهيار حتمي، ولا علاقة له بحروف بعينها: جُرّب بإزالة
كل حروف رسم الصناديق من التعليقات فانتقل الانهيار إلى حرف عربي عادي.

`next build --webpack` خيار رسمي مدعوم ويعطي المخرجات نفسها. أزل العلم
حين تُصلَح العلّة في Next.


### دخول مؤقت بكلمة مرور

الدخول الأساسي برمز على البريد، فإن لم يكن SMTP جاهزًا لا يمكن الدخول
إطلاقًا. لتجاوز ذلك مؤقتًا لصاحب المنصة:

```
ALLOW_PASSWORD_LOGIN="true"
OWNER_EMAIL="you@example.com"
OWNER_PASSWORD="كلمة-مرور-قوية-12-حرفًا-فأكثر"
```

يظهر عندها خيار «الدخول بكلمة المرور» في `/login`.

**حدوده مقصودة:** حساب واحد فقط، لا تسجيل ولا استعادة، ورسالة فشل
موحّدة لا تكشف أي الحقلين كان خاطئًا، ومحاولات محدودة (5 لكل بريد و10
لكل IP كل 15 دقيقة ثم حظر ساعة). كل دخول يُسجَّل في `AuditLog`.

**احذف `ALLOW_PASSWORD_LOGIN` فور عمل البريد.** المسار يرد 404 بدونه.

## الأمان

| الجانب | التنفيذ |
| --- | --- |
| **الجلسات** | رمز عشوائي 256 بت، يُخزَّن **هاشه** فقط (SHA-256). كوكي `httpOnly` + `secure` + `sameSite=lax`. قابلة للإبطال فورًا — الإيقاف الإداري يقتل كل الجلسات. |
| **رموز التحقق** | 6 أرقام من `randomInt` المشفّر، مُخزَّنة بهاش **bcrypt**. صلاحية 10 دقائق، استخدام واحد، حد 5 محاولات، وإبطال الرموز السابقة عند طلب جديد. |
| **تعداد الحسابات** | `/api/auth/request-otp` يرد بنفس الرسالة سواء كان البريد مسجّلًا أم لا. رسائل فشل التحقق موحّدة (لا تفرّق بين رمز خاطئ ومنتهٍ). |
| **تحديد المعدّل** | على طلب الرمز (لكل بريد ولكل IP)، والتحقق، والكتابة، والرفع. |
| **CSRF** | `sameSite=lax` + فحص `Origin` صريح على كل طلب تغيير حالة. |
| **عزل البيانات** | كل استعلام مقيّد بـ `userId` من الجلسة. تعديل حساب يطابق `{ id, page: { userId } }` — تخمين المعرّف لا يكفي. |
| **حدود الباقات** | مفروضة على **الخادم** (عدد الحسابات، الثيمات، اللون المخصص، إزالة العلامة) لا في الواجهة فقط. |
| **رفع الصور** | فحص التوقيع الثنائي (لا نثق بـ `Content-Type`)، ثم **إعادة ترميز كاملة** بـ sharp إلى WebP — يُسقط EXIF وأي حمولة مضمّنة. تُخدم بـ `nosniff` و`CSP: sandbox`. |
| **الويب هوك** | تحقق توقيع HMAC بمقارنة ثابتة الزمن على الجسم الخام قبل أي معالجة. مع idempotency لمنع التفعيل المكرر. |
| **رؤوس HTTP** | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, و`HSTS` في الإنتاج. |
| **XSS** | React يهرّب كل النصوص؛ لا `dangerouslySetInnerHTML` في المشروع، ولا مدخلات HTML. |
| **الأخطاء** | لا تُسرَّب تفاصيل الاستثناءات للمستخدم — معرّف فقط للدعم. |
| **الأسماء المحجوزة** | قائمة تمنع أسماء مستخدمين تنتحل مسارات المنصة (`admin`, `api`, `login` …). |

### تحقق الآيبان — حدوده

`src/lib/iban.ts` يطبّق **ISO 13616** كاملًا: بنية الرمز، طول الدولة، وخانة
التحقق **mod-97-10**. مُختبَر على 8 حالات (سعودي وبريطاني وألماني، صحيح
وخاطئ).

**ما لا يفعله — بوضوح:** لا يتحقق من وجود الحساب، ولا من كونه نشطًا، ولا من
ملكيته لمن أدخله. التحقق من الملكية يتطلّب تكاملًا بنكيًا خارج نطاق المنصة.
هذا مذكور صراحةً للزائر أسفل كل صفحة عامة.

## ما جرى التحقق منه

اختبار طرف-إلى-طرف بمتصفح حقيقي (Playwright)، **18 فحصًا نجحت كلها**:

- الرئيسية والصفحة العامة تعملان (HTTP 200)، وزر النسخ يُظهر «تم النسخ»
- الآيبان يُعرض LTR داخل صفحة RTL، ورمز QR يُولَّد ويُنزَّل
- `/dashboard` بلا جلسة يعيد التوجيه إلى `/login`
- `/admin` لمستخدم عادي يعيد التوجيه إلى `/dashboard`
- تدفق الدخول كامل: طلب رمز ← رفض رمز خاطئ ← قبول الصحيح ← إنشاء الصفحة
- آيبان بخانة تحقق خاطئة **مرفوض**، والصحيح مقبول
- حد الباقة المجانية (3 حسابات) يُفرَض ورسالته تظهر
- صفحة غير موجودة ترد 404
- `npm run typecheck` نظيف، ولا أخطاء في وحدة تحكم المتصفح

## ملاحظات للإنتاج

1. **`APP_SECRET`** — ولّده عشوائيًا لكل بيئة، ولا تشاركه.
2. **تحديد المعدّل في الذاكرة** — كافٍ لخادم واحد. مع أكثر من نسخة استبدل
   التخزين في `src/lib/ratelimit.ts` بـ Redis؛ واجهة `consume()` تبقى كما هي.
3. **الصور في قاعدة البيانات** — مختارة لقابلية النقل. مع نمو الاستخدام
   انقلها إلى تخزين كائنات (S3/R2) وأبقِ `/api/media/[id]` كوسيط.
4. **CSP** — الرؤوس الأساسية مضبوطة في `next.config.ts`. لإضافة
   `Content-Security-Policy` كامل للسكربتات يلزم nonce عبر middleware.
5. **تنظيف دوري** — احذف `OtpCode` و`Session` المنتهية بمهمة مجدولة.
